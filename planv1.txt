SECTION 2 — SYSTEM LEAKAGES & TECHNICAL GAPS IDENTIFIED
================================================================================

1. Wayland Input/Idle Telemetry Leakage (Linux)
   - Problem: Reading /dev/input/event* requires root or input group privileges. Standard non-root users will encounter PermissionDenied on Linux Wayland (GNOME/KDE).
   - Solution: Use D-Bus calls to org.gnome.Mutter.IdleMonitor or org.freedesktop.ScreenSaver (GetSessionIdleTime) instead of raw device handles.

2. Headless Windows Session Watcher (WTS Notifications)
   - Problem: WTSRegisterSessionNotification requires an active Win32 message loop (HWND). In --background mode, Avalonia GUI is skipped, so background threads lack a message pump.
   - Solution: SystemEventWatcher on Windows must create a hidden message-only window (HWND_MESSAGE via P/Invoke CreateWindowEx) when running in background mode.

3. Sleep / Wake Network & Skew Spikes
   - Problem: System clocks drift during OS sleep, and network interfaces take several seconds to re-establish upon wake.
   - Solution: Introduce a 10-second post-resume stabilization delay before triggering sync or clock skew calculations.

4. SQLite Lock Contention Under 5 Hosted Services
   - Problem: AttendanceAggregator reads app_sessions and session_events while SyncService drains rows and LogCollectorService writes heartbeats. A single SemaphoreSlim(1,1) will cause database lock timeout stalls.
   - Solution: Enable Write-Ahead Logging (PRAGMA journal_mode=WAL;) and use dedicated read connections for background aggregators.

5. In-Memory Aggregation Risk vs. Sudden Shutdown
   - Problem: Buffering events in memory for 5 minutes risks losing telemetry on abrupt power loss or SIGKILL (kill -9).
   - Solution: Persist events to SQLite immediately upon capture with is_synced = 0. Perform 5-minute aggregation during the SyncService drain phase when constructing server network payloads.

SECTION 3 — CROSS-PLATFORM & SCALABILITY ARCHITECTURE
================================================================================

1. Client Daemon Architecture (.NET 8 + Avalonia):
   - Headless First: Keep the background tracker daemon decoupled from UI (--background mode). Avalonia GUI is created lazily on IPC signal.
   - Native OS Subsystems:
     * Linux: D-Bus interfaces (UPower, logind, org.gnome.ScreenSaver, Mutter.IdleMonitor).
     * Windows: Hidden HWND_MESSAGE pump for WTS notifications + GetLastInputInfo.
     * macOS: NSWorkspace notifications + CGEventSourceSecondsSinceLastEventType.

2. Storage Layer (Client SQLite):
   - Enable PRAGMA journal_mode=WAL; and PRAGMA synchronous=NORMAL;.
   - Cap maximum local session_events rows (ALPHA_TA_MAX_LOCAL_ROWS = 50,000) with automatic sentinel rollup for offline resilience.

3. Transport Layer (Client -> Go Backend):
   - Payload Aggregation: Roll up identical lock/unlock events into 5-minute summary buckets during sync drain.
   - Adaptive Compression: Compress payloads using gzip (SyncMaxBytes bounded) to keep client RAM < 50 MB and server load minimal at 10,000+ agents.

SECTION 4 — TARGET STATE & VOCABULARY
================================================================================

Session Event Types (Single Source of Truth):
- power_on       : PC booted or tracker service started
- power_off      : Graceful OS shutdown or service stop recorded
- resume         : OS resumed from sleep / suspend
- os_login       : User authenticated into OS session
- os_logout      : User logged out of OS session
- screen_lock    : Display locked or screen saver active
- screen_unlock  : Display unlocked
- tracker_login  : Employee signed into the tracker application

SQLite Schema Extensions (v12 / v13):
1. employee_schedule (PK: employee_id)
2. company_holidays (PK: holiday_date)
3. daily_attendance_cache (PK: employee_id, work_date)
4. local_time_skew (PK: server_url)
