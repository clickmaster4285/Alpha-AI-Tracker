SECTION 0 — RULES THIS PLAN MUST OBEY
================================================================================

R1  Installer-Parity Rule (HIGHEST).
    A change is NOT complete until verified in an installed build
    (`bash publish/build-installer.sh -b linux && sudo dpkg -i ...`).
    `dotnet run` is for fast iteration only and cannot catch packaging gaps.

R2  No-Hardcoded-Names Rule.
    Software / OS event names MUST come from OS metadata, not product-name
    lists. The three "structural" wins we keep using:
      - Linux:  D-Bus interface names (org.freedesktop.UPower,
                org.freedesktop.login1, org.gnome.ScreenSaver,
                org.gnome.Mutter.IdleMonitor)
      - Windows: Win32 API + WTS subsystem + hidden HWND_MESSAGE pump
      - macOS:   IOKit / NSWorkspace / CGEventSource / CGSession
    No "If process name == 'logonui' then login" hacks. No "If window
    title contains 'Sign in' then login". The OS event IS the truth.

R3  Branding-Single-Source Rule.
    The product name and version come from ONLY:
        client/APP_IDENTIFIERS
        client/VERSION
    Any literal brand string or version number in any other file, XAML,
    or script is a bug to be fixed. This plan adds zero new literals.

R4  Web Infinite-Scroll Rule + Server-Projected Flags Rule.
    Apply to Phase 2 web pages (flagged, not built here).

R5  Single Source of Truth for new event types.
    New event_type strings ("power_on", "screen_lock"…) live in ONE
    constant class in `client/Core/Models/SessionEvent.cs` with a doc
    comment. Server mirror lives in `server/internal/models/session_event.go`.
    The web renders them via the same constant set in
    `web/src/lib/eventTypes.ts`. Cross-service drift is caught by an
    integration test (see §10).

R6  Path Discipline (AGENTS.md §6 "Installer-Parity Rule" item 6).
    The installed app's working dir is root-owned and unwritable. All
    runtime files use:
        Linux:   ~/.config/alpha-ai-tracker/  (config, logs)
                 ~/.local/share/alpha-ai-tracker/ (DB, sockets, cache)
        Windows: %LocalAppData%\AlphaAITracker\  (everything)
        macOS:   ~/Library/Application Support/AlphaAITracker/
    Never write to AppDomain.CurrentDomain.BaseDirectory on Linux.

R7  Shutdown-Sentinel Robustness Rule.
    The ShutdownSentinel MUST write power_off BEFORE any hosted service
    stops. In background mode, Program.cs runs `Task.Delay(Timeout.Infinite)`.
    SIGTERM cancels that delay via the host's CancellationToken, but the
    sentinel must race the host shutdown. Design: sentinel is the FIRST
    hosted service registered; it holds a ManualResetEventSlim that the
    Program.cs shutdown path signals AFTER the sentinel completes.

R8  SQLite Concurrency Rule.
    The existing single-connection + SemaphoreSlim(1,1) gate in
    SqliteLogStore will DEADLOCK under 5+ hosted services (SyncService,
    AttendanceAggregator, ScheduleCacheService, etc.). WAL mode +
    dedicated read connection is MANDATORY before Phase 1 ships.

S1  Aggregated session_events sync.                           [DONE — A.9 (2026-09-01)]
    Today every lock/unlock = 1 row. The new SessionEventRecorder
    groups events into 5-minute rolling buckets per (employee_id,
    event_type) before the SyncService drains.
    Tunable via ALPHA_EVENT_AGGREGATION_WINDOW_SEC (default 300).

S2  Per-employee sub-batches in SyncService.                  [N/A — single employee per desktop client]
    Drain loop keys on (employee_id, table) and runs sub-batches
    in parallel via Task.WhenAll with ALPHA_SYNC_PARALLELISM cap
    (default 4).

S3  High-water-mark keys in app_status.                       [PARTIALLY DONE]
    ta_last_known_os_event_at key is documented for A.3 to write.
    ta_last_schedule_pull_at, ta_last_aggregator_run_at, and
    ta_last_skew_measure_at are reserved for A.6, A.8, A.7.

    New `timezone` column on employee_info (handled in A.6).

    Added (event_type, event_at) and (employee_id, event_at)
    on session_events. (employee_id, work_date) on

S6  Local cache is a hard ceiling, not a soft one.            [DONE — A.10 (2026-09-01)]

SECTION 7 — BUGS FOUND DURING CODEBASE AUDIT
================================================================================

BUG-1  Power-off time is unobservable.                          [DONE (A.0/A.1/A.2/A.5) in A.2]
        Program.cs background mode: `Task.Delay(Timeout.Infinite)` at
        line 321. SIGTERM cancels the token -> TaskCanceledException
        -> falls through to host.StopAsync() at line 329. NO event
        is recorded during this path.
        Fix: ShutdownSentinel (§3 NEW, §2.6) with R7 rule.

BUG-2  "login" is the only event_type ever written.             [DONE (A.0/A.1/A.2/A.5) in A.1]
        LogCollectorService.cs:183. The model comment (DeviceHardwareInfo.cs:131)
        lists "login | logout | lock | unlock" but no code path emits
        any of them. The model misleads future contributors.
        Fix: SessionEventTypes (§4) + LogCollectorService edit.

BUG-3  Window.Closing hides-to-tray without writing any event.  [DONE (A.0/A.1/A.2/A.5) in A.2]
        App.axaml.cs:53–60. When the user clicks the X on the window,
        the app goes to tray but no event is recorded. From the
        dashboard's perspective the employee is "active" forever.
        Fix: ShutdownSentinel covers this — the Avalonia Exit event
        fires when AllowShutdown is set, and the window.Closing handler
        now also calls IEventRecorder.RecordAsync("ui_hidden").

BUG-4  Graceful shutdown via Ctrl+C is silent.                   [DONE (A.0/A.1/A.2/A.5) in A.2]
        Program.cs: the background-mode try/finally at line 265–336
        catches host.StopAsync but never records the event.
        Fix: Console.CancelKeyPress hook in Program.cs, delegates to
        ShutdownSentinel. The sentinel's hosted-service position (FIRST
        in DI) ensures it writes before other services stop.

BUG-5  AllowShutdown is set by AppUpdateService, NOT MainViewModel. [DONE (A.0/A.1/A.2/A.5)]
        The planv1.txt says "Locate AllowShutdown setter in
        MainViewModel" — this is WRONG. App.axaml.cs:15 declares it;
        AppUpdateService.cs:310 and :924 are the ONLY call sites.
        Fix: update all plan references.

BUG-6  Schedule data exists only on the server.                  [PENDING — A.6 (ScheduleCacheService fills the tables created in A.5)]
        The T&A module is meaningless without "what was the
        employee's assigned shift today". The client has zero
        notion of a shift.
        Fix: ScheduleCacheService + new SQLite tables
        (employee_schedule, company_holidays) + new server
        endpoint (SVR-1).

BUG-7  Local clock skew is invisible.                            [PENDING — A.7]
        Today the dashboard shows "late by 5 min" using the
        client's local clock with no sanity check. A 4-minute
        skew is the difference between "late" and "on time".
        Fix: LocalTimeSkewService (§2.7) + new SQLite table.

BUG-8  No "is the OS event watcher actually running?" signal.    [PENDING — A.3]
        The existing dashboard IsSyncHealthy is based on
        last_heartbeat_at. A stuck SystemEvents.PowerModeChanged
        subscription (rare but possible) wouldn't be visible.
        Fix: SystemEventWatcher writes ta_last_known_os_event_at to
        app_status on EVERY received event, regardless of type.

BUG-9  SQLite single-connection gate will deadlock under 5+ services.  [DONE (A.0/A.1/A.2/A.5) in A.5]
        SqliteLogStore uses SemaphoreSlim(1,1) on ONE connection.
        AttendanceAggregator, SyncService, LogCollectorService, and
        ScheduleCacheService all hit SQLite concurrently.
        Fix: WAL mode + dedicated read connection (R8, §2.8, S9).

BUG-10 Wayland idle detection via /dev/input is wrong.            [PENDING — A.4 (IdleDetector)]
         planv1.txt gap #1: reading /dev/input/event* requires root
         or input group membership. Standard non-root users get
         PermissionDenied on GNOME/KDE Wayland.
         Fix: Use D-Bus org.gnome.Mutter.IdleMonitor.GetSessionIdleTime
         on Wayland. Fall back to "no foreground focus" heuristic.

BUG-11 Windows WTS notifications need a hidden message pump.      [PENDING — A.3]
         planv1.txt gap #2: WTSRegisterSessionNotification requires
         an active Win32 message loop (HWND). In --background mode,
         Avalonia GUI is skipped, so background threads lack a pump.
         Fix: SystemEventWatcher on Windows creates a hidden
         HWND_MESSAGE window (CreateWindowEx with HWND_MESSAGE) when
         running in background mode.

BUG-12 Sleep/wake triggers sync spikes + skew misreads.           [PENDING — A.7]
         planv1.txt gap #3: system clocks drift during OS sleep, and
         network interfaces take seconds to re-establish on wake.
         Fix: 10-second post-resume stabilization delay in
         LocalTimeSkewService and ScheduleCacheService before
         triggering sync or clock-skew calculations.

BUG-13 In-memory aggregation loses data on SIGKILL.               [DONE (A.0/A.1/A.2/A.5) in S1]
         planv1.txt gap #5: buffering events in memory for 5 minutes
         risks losing telemetry on abrupt power loss or SIGKILL.
         Fix: persist events to SQLite immediately upon capture with
         is_synced = 0. Perform 5-minute aggregation during the
         SyncService drain phase when constructing server network
         payloads. The local DB is the source of truth; the sync
         payload is a derived view.

SECTION 11 — RISK REGISTER
================================================================================

  R-MED  macOS Accessibility permission flow.                       [PENDING]
          If the user denies the prompt, SystemEventWatcher on
          macOS is silent. Mitigation: dashboard surfaces a
          "Permissions required" banner (existing pattern from
          PermissionSetupPage). Settings -> Tracking links the
          user to System Settings -> Privacy.

  R-MED  Windows WTS notifications require a window message          [PENDING]
          pump. The new code must subscribe on a hidden HWND_MESSAGE
          window, not a background thread, or the callback never
          fires. Mitigation: create the HWND in SystemEventWatcher's
          StartAsync and destroy it in StopAsync.

  R-MED  systemd Stop signal on Linux might not give the             [DONE (A.0/A.1/A.2/A.5)]
          ShutdownSentinel its 2s budget. Mitigation: write
          synchronously to a tiny "pending_events" file in the
          user config dir FIRST (1 syscall), then promote to
          SQLite on next boot. Belt-and-suspenders.

  R-MED  SQLite WAL + read connection regression.                   [DONE (A.0/A.1/A.2/A.5) in A.5]
          If the read connection is opened before WAL is enabled,
          it gets a legacy rollback journal and readers still block
          writers. Fix: enable WAL FIRST, then open the read conn.

  R-LOW  D-Bus interface name drift on Wayland compositors.
          GNOME has org.gnome.ScreenSaver, KDE has its own.
          Mitigation: try a list of well-known interface names
          in priority order; the first one that responds wins.
          Log which one is active.

  R-LOW  LogCollectorService is the busiest single file in
          the project. Adding 3 more event writes risks
          coupling drift. Mitigation: ALL writes go through
          IEventRecorder. LogCollectorService never touches
          session_events directly.

  R-LOW  Daily attendance cache may diverge from the server's
          own aggregator (Phase 2). Mitigation: the cache is
          a presentation hint, not a source of truth. The
          server aggregator always wins. The cache is
          refreshed on every local event; the server side
          re-computes on read.

  R-LOW  R3 (Branding) violation risk: this plan adds a
          new app_status key prefix ("ta_") which is fine;
          do NOT add a new brand string. Audit before merge.

  R-LOW  R1 (Installer-Parity) violation risk: the new
          SystemEventWatcher uses only OS APIs that are
          already on the target machines. No new binary
          asset. If we later need an X11 helper (libXss),
          we MUST add it to bundle_into_publish() AND
          build-deb.sh AND build-dmg.sh AND
          installer-windows.iss. (No X11 on Windows; skip
          the .iss entry.)

      | Platform | Primary API / path              | Typical accuracy |
      |----------|---------------------------------|------------------|
      | Windows  | Windows.Devices.Geolocation       | 10–500 m (WiFi)  |

        fusion, not survey-grade GPS.

        Linux polkit for GeoClue). Denied permission → no fix or IP-only.
      - Battery/network: poll on an interval, not continuous high-rate GPS.
      - Employee consent: default OFF (ALPHA_LOCATION_ENABLED=false).
