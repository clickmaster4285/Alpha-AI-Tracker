FreeBuff Plan — "Always track the user's normal browser" + hardening fixes
==========================================================================

Date: 2026-08-05
Author: FreeBuff (resuming from the uncommitted Copilot diff on brandnewBrowserjourneytrack)

GOAL (user requirement)
----------------------
- Employees open their browser the normal way (double-click). They know nothing
  about debug ports.
- During installation the tool obtains consent / OS permissions, and the
  requirement is: THE USER'S BROWSER IS ALWAYS TRACKED — including a normal
  double-click launch.
- Additionally: fix the other issues collected during analysis.

THE CORE PROBLEM
----------------
Chrome 136+ ignores --remote-debugging-port when the browser is launched with
the DEFAULT user data directory. A normally-launched browser can never be
debugged retroactively — you can only attach to a browser that was STARTED with
the flag (or that has DevToolsActivePort).

Current (uncommitted) code removed the "hijack" (kill + relaunch real profile)
and only launches a DEDICATED debug instance on a separate profile. That means:
  - the employee's real browsing is NOT captured at all,
  - an extra browser window appears that the employee didn't open.
This fails the requirement. (Verified on this machine: Chrome 151; a fresh
profile + debug port works — HTTP 200 — so the mechanism is fine, the default-
profile path is the problem.)

THE FIX — tiered attach, real-profile first (permission granted at install)
---------------------------------------------------------------------------
ChromiumEngineAdapter.LaunchAndConnectAsync is re-ordered so the REAL profile is
always preferred, the dedicated instance is only a last resort:

  0. Real profile has DevToolsActivePort  -> attach (never touch it).
  1. Real browser already exposes a debug port (any chrome with the flag that
     is NOT our dedicated instance) -> attach.
  2. Real browser running WITHOUT a debugger (auto-launch on):
     -> HIJACK (permission-approved): terminate the browser (preserving our
        dedicated debug instance), relaunch the SAME real profile with an
        explicit --user-data-dir=<real profile> + --remote-debugging-port.
        - Chrome <136: works, real browsing tracked.
        - Chrome 136+ if same-path --user-data-dir is allowed: works.
        - Chrome 136+ if blocked: port never opens -> clean up stray, fall
          through to step 5.
        - Cooldown (new knob ALPHA_BROWSER_HIJACK_COOLDOWN_MINUTES=3) prevents
          kill-loops. THIS RESTORES THE OLD hijack behaviour the user wants.
  3. Nothing running (auto-launch on): launch the real profile with the flag
     (same explicit --user-data-dir); on failure clean up the stray.
  4. Leftover debug instance of this browser (our dedicated dir or any chrome
     with a debug flag) -> attach (recovery across tracker restarts).
  5. Dedicated debug instance (separate profile) -> last resort only.

Supporting changes:
  - BrowserProcessProbe.IsRunning / TerminateInstances gain an
    "exclude/preserve cmdline token" parameter so the tracker never treats its
    own dedicated debug instance as "the user's real browser" and never kills
    it during a hijack.
  - New RunningBrowserProbe: detects browsers that are RUNNING but not yet in
    the installed-apps catalog (catalog scan runs every ~15 min). Closes the
    "install new browser -> use it -> uninstall within 5 minutes" gap (Q3):
    the tracker now sees the running binary immediately, resolves its real
    profile, and can hijack/attach it.

OTHER FIXES FROM THE ANALYSIS (all in this plan)
------------------------------------------------
1. Ephemeral-tab dead branch (BrowserJourneyEngine):
   The delayed persist task's "ephemeral TTL drop" else-if was unreachable
   (the delay equals the persist threshold, so age >= threshold is always
   true). Simplified: after the threshold a still-open tab is persisted
   (time-based guarantee); per-tab ephemeral dropping is handled by
   CloseTabAsync (tabs closed before the threshold are dropped) and by the new
   idle sweep. BrowserEphemeralTtlSec remains in use for runtime GC.
2. Download watcher (BrowserJourneyEngine):
   - Skip writing items when no open tab matched (prevents orphan rows with an
     empty app_session_id that join to nothing locally or on the server).
   - Read _openByTab under the engine gate (was a threadpool race, async void).
   - Case-insensitive dedup of the Downloads paths (Windows case-insensitive FS
     would otherwise record every file twice).
   - Set TabId on download items for consistent ordering.
3. Wire the 5 dead config knobs (were parsed but never read):
   - BrowserJourneyIdleMinutes -> NEW idle-close sweep in the JourneyEngine
     (closed by the watchdog every 60s). Prevents week-old open sessions
     (Q1). Recovered/persisted tabs get LastNavAt = now so they are not
     instantly closed.
   - BrowserReconnectBaseSeconds / BrowserReconnectMaxSeconds -> exponential
     reconnect backoff in BrowserConnectionManager (was a hardcoded 10s).
     Defaults changed 1/30 -> 5/60.
   - BrowserStartDebounceSec -> BrowserRuntimeManager skips attach attempts
     within N seconds of first sighting (suppresses restart churn).
   - BrowserCoordinatorDedupSeconds -> BrowserEventCoordinator dedup sweep
     window (was hardcoded 5s).
   - NEW knob ALPHA_BROWSER_HIJACK_COOLDOWN_MINUTES (default 3) replaces the
     removed hardcoded 5-min hijack cooldown.
4. Installer parity: all knobs are added to client/.env (not just .env.example)
   so encrypt-config.sh bakes them into config.enc for installed builds.
5. Program.cs: pass dedup seconds + hijack cooldown into the coordinator and
   adapters; fix the mis-indented BrowserRuntimeManager factory (cosmetic).

EXPLICITLY OUT OF SCOPE (documented, not silent)
------------------------------------------------
- Network-level fallbacks (pcap/SNI) — notstarted in updateplan, deferred.
- browser_profiles / browser_tabs tables from updateplan — tabs/profiles stay
  in-memory; open journeys are persisted in browser_journeys + open app_items
  (recovery works). Revisit only if UI needs persisted profile tables.
- Extension/native-messaging path — removed in the client; not resurrected.
- Chrome policy drop (RemoteDebuggingAllowed) — unverified for the 136+ block;
  can be added to the installer as a best-effort step if the hijack test shows
  the same-path --user-data-dir is still blocked.

   session; cycles < 30s produce no rows.

6. dotnet build clean; then bash publish/build-installer.sh and re-run 1-5 from
   the installed build (mandatory).

   The goal is ACHIEVED only on Chrome <136 and flag-honoring Chromium builds.

═ PIVOT — OPTION B: ACCESSIBILITY-TREE BROWSER JOURNEY (SHIPPED 2026-08-05) ═
--------------------------------------------------------------------------
The user chose Option B (no extension, no debugger): read the OS accessibility
tree — the SAME tree screen readers use — to see the employee's REAL browser
windows on every platform and every Chrome version, including the install→use→
uninstall-in-5-minutes and never-restarts-for-a-week scenarios.

EMPIRICAL VALIDATION on this machine (Chrome 151, live window):
  - Browser windows are AT-SPI FRAME(23)/WINDOW(69) nodes under the app root.
  - The omnibox is an ENTRY(79) node named "Address and search bar" whose Text
    is the EXACT current URL/query — captured live:
      "google.com/search?q=distorable+mean&sca_esv=..." (full query in the URL)
  - Page title = FRAME Name; PAGE_TAB nodes = tabs. Headless instances skipped.
  - AT-SPI2 D-Bus quirk: Name/Role are Properties.Get, GetChildren is a method,
    text comes from org.a11y.atspi.Text.GetText. python3-dbus is present on
    GNOME desktops (falls back gracefully when absent).

WHAT WAS SHIPPED (client/Core/BrowserAccessibility/):
  - IAccessibilityBrowserReader + AccessibilitySnapshot (window key, pid,
    process name, title, normalized URL, incognito flag).
  - LinuxAtSpiBrowserReader — python3 + AT-SPI probe (embedded script, no extra
    files → installer parity), JSON output, 8s subprocess timeout, URL
    normalization (omnibox shows no scheme → prepend https://), per-window
    incognito detection (one incognito window never flags its siblings).
  - WindowsUiaBrowserReader — UIA via Interop.UIAutomationClient (netstandard2.0
    package; verified API surface by reflection) — "Address and search bar"
    edit's ValuePattern = exact URL.
  - MacOsAccessibilityBrowserReader — osascript/System Events (title always;
    address-bar value best-effort; requires the Accessibility grant).
  - AccessibilityBrowserTracker (BackgroundService) — polls every N s
    (ALPHA_BROWSER_ACCESSIBILITY_POLL_SECONDS=3), one app_session per window +
    browser_tab root item + browser_navigation items on URL change, idle-close
    after ALPHA_BROWSER_JOURNEY_IDLE_MINUTES=15, missing-window close after 3
    polls, graceful close on shutdown (no orphans), incognito URL capture gated
    by ALPHA_BROWSER_CAPTURE_INCOGNITO=false (legal-safe default), download
    watcher (browser_download items) attached to the most recent session.
  - Also fixed: SqliteLogStore fuzzy-match AND/OR precedence bug (was returning
    the junk 'chrome' row instead of 'Google Chrome'; now prefers is_browser
    rows + shortest binary).

REMOVED AS DEAD (per user request "remove dead code, unwanted code, db etc."):

  - AppConfig/.env/.env.example: all debugger knobs removed; 4 a11y knobs added.
