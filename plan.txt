─── 0a. Fix the GUI-only gate ─────────────────────────────────

CURRENT STATE (from live DB audit of 48 open sessions):
  47 of 48 open sessions have installed_app_id (only 1 orphan).
  But NON-GUI processes are passing through the gate:

  Leaking process         Resolves via              Root cause
  ─────────────────────────────────────────────────────────────────
  sh (binary_name='sh')   IN installed_applications  Old auto-register created row before GUI gate
  bash                    Fuzzy match to sh          SQL: 'bash' LIKE '%sh%' → TRUE
  ssh-agent (sh display)  Fuzzy match to sh entry    Same fuzzy issue  
  unattended-upgrade-shutdown  Fuzzy match to sh     Same fuzzy issue
  snap                    IN installed_applications   Old auto-register ("Handler for snap:// URIs")

  WHY THE GATE FAILS:
  ResolveAppInfoInner has 4 steps:
    Step 1: Check _knownAppBinaryNames (loaded from DB) → hit if sh/snap are in installed_applications
    Step 2: Fuzzy match via GetInstalledAppByBinaryNameFuzzyAsync → bash→sh via LIKE '%sh%'
    Step 3: IsGuiApplication() check → NEVER REACHED for these because step 1/2 catches them first
    Step 4: Skip

  The GUI gate (step 3) is ORDERED LAST — pre-existing DB rows bypass it entirely.

  WHAT TO FIX:
  [ ] Add IsGuiApplication gate to step 1: even if process is in installed_applications,
      only track it if it's actually a GUI app (has Categories field non-empty, is_browser=true,
      or passes a lightweight GUI check). Skip non-GUI rows even if they exist in the DB.
  [ ] Add to NonAppProcesses: "sh", "bash", "zsh", "dash", "fish", "ssh-agent",
      "unattended-upgrade-shutdown", "snap", "file-manager", "gvfsd-trash"
  [ ] Add prefix filters for VS Code subprocesses: "Microsoft." (catches .NET language servers,
      VS Code extension hosts, SQL tools, etc.)
  [ ] Fix fuzzy match: GetInstalledAppByBinaryNameFuzzyAsync should exclude binary_names that
      match system processes, or require minimum match length > 2 characters.
  [ ] Clean up existing garbage rows: DELETE installed_applications entries for sh, snap
      (no real .desktop file), and close their open app_sessions.

  links for IDE→shell→buildTool relationships, not same-app subprocesses.

  ⚠️ CORRECTION (user review 2026-07-30): app_items ALREADY has an
  action column (added with the file-manager journey engine). No schema
  change needed. Phase 2 is simpler than originally written.

  CORRECT APPROACH:
  [ ] When a new session is created, write an app_items row with:
        object_type = 'AppSession'
        action = 'open'
        title = appDisplayName
        occurred_at = started_at
  [ ] When a session is closed, write:
        object_type = 'AppSession'
        action = 'close'
        occurred_at = ended_at
  [ ] This gives callers ONE table (app_items) to query for open/close/nav/
      foreground/background across all app types. No schema changes needed.

─── 0c. Fix parent_process_id population ──────────────────────

  CURRENT STATE:
  parent_process_id is NULL on 100% of all app_sessions rows (0 of 48 open, 0 of 130 total).

  Root cause: SessionHierarchyResolver.ResolveParent() only returns a link when
  ShouldLinkTo() explicitly allows it. The ShouldLinkTo matrix is:

    Parent IDE → accepts: shell, terminal, runtime, buildTool
    Parent Terminal → accepts: shell, runtime, buildTool
    Parent terminal-item → accepts: shell, runtime, buildTool
    Parent tab-item → accepts: shell
    All others → NEVER links

  This means:
  - VS Code → bash → npm: links WORK (IDE→shell→buildTool chain)
  - VS Code → extension host: NO LINK (not in matrix)
  - gnome-terminal → bash → npm: links WORK (terminal→shell→buildTool)
  - chrome → chrome-extension-host: NO LINK

  The common case (bash inside gnome-terminal) should work, but doesn't because:
    gnome-terminal is registered as installed_app with item_type="tab" (not "terminal")
    so ShouldLinkTo checks parent.ItemType == "tab" → only accepts IsShellInterpreter → bash ✓
    BUT: the PPID of bash might skip gnome-terminal and go directly to systemd/init.

  WHAT TO FIX:
  [ ] Add debug logging to ResolveParent showing PPID chain walks
  [ ] Handle the common case: if parent has item_type="tab" and child is shell_process → link
  [ ] Add same-installed-app-id linking: if parent and child share installed_app_id → link
  [ ] Ensure gnome-terminal actually gets item_type="terminal" via its .desktop Categories
  [ ] After creating a new session, verify parent_process_id is set and log warning if not

─── 1a. Generalize ATSPIEventWatcher for all apps ─────────────

  ⚠️ CORRECTION (user review 2026-07-30): AT-SPI's focus: signal fires
  on EVERY widget-level focus change (text field, dropdown, menu), not just
  top-level window switches. Generalizing without a filter would flood the
  interval table with noise — an app_focus_intervals row every time someone
  clicks into a different text box.

  WHAT TO BUILD:
  [ ] Gate on AT-SPI window-level activation signals (window:activate/
      window:deactivate) rather than the generic per-widget focus: signal.
      These are already distinguished in the AT-SPI event stream.
  [ ] Add short debounce (reuse existing 3s dedup from EventCoordinator) so
      rapid alt-tab flicker doesn't generate sub-1s noise intervals.
  [ ] Extend ATSPIEventWatcher to emit IObservableEventSource events for ALL
      app window activation changes, not just file managers.
  [ ] Track _lastFocusedPid and emit "background" event for previously-focused
      window before emitting "foreground" for new one.
  [ ] Emit RawDesktopEvent with:
      object_type = "Window"
      action = "foreground" | "background"
      Source PID, window title, timestamp
  [ ] Keep existing file-manager path detection (cwd resolution) as-is — just
      make it conditional on IsFileManagerProcess.

─── 1b. New table: app_focus_intervals ────────────────────────

  [ ] Add CREATE TABLE to DatabaseSchema.cs:

      CREATE TABLE IF NOT EXISTS app_focus_intervals (
          id              TEXT PRIMARY KEY,
          app_session_id  TEXT NOT NULL REFERENCES app_sessions(id),
          state           TEXT NOT NULL CHECK(state IN ('foreground','background')),
          occurred_at     TEXT NOT NULL,
          duration_seconds INTEGER,        -- filled when next interval starts
          created_at      TEXT DEFAULT (strftime('%Y-%m-%dT%H:%M:%S.000Z','now'))
      );

  [ ] Add methods to ILogStore / SqliteLogStore:
      - StoreFocusIntervalAsync(AppFocusInterval interval, CancellationToken ct)
      - GetUnclosedFocusIntervalsAsync(CancellationToken ct) → open-ended intervals
      - CloseFocusIntervalAsync(string id, int durationSeconds, CancellationToken ct)

─── 1c. Boot reconciliation for app_focus_intervals ───────────

  [ ] In ReconcileStaleSessionsOnBootAsync, ALSO close any dangling open
      focus intervals using lastHeartbeat as the approximate end time.
      Same pattern: query open intervals, close with heartbeat timestamp.

─── 1d. Reuse JourneyEngine ───────────────────────────────────

  [ ] In JourneyEngine.ProcessEventAsync(), add a branch for:
      if (e.ObjectType == "Window" && e.Action is "foreground" or "background"):
