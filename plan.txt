# Alpha AI Tracker — Server DB Washout + Full-Data Sync Preparation

## Findings

**DB state (`alpha_ai_tracker`, PostgreSQL running):**
- 5 employees (EMP-10002 … EMP-10010), 1 admin user, 8 departments, 12 migrations applied
- Tracking data to wipe: `app_sessions` 9,976 / `app_items` 10,223 / `installed_applications` 5,548 / `installed_packages` 6,530 / `device_hardware_info` 716 / `network_info` 46 / `session_events` 46 + 6 empty legacy tables (`browser_contexts`, `file_explorer_contexts`, `shell_commands`, `urls`, `url_visits`)
- Server builds clean; all 7 sync endpoints wired; running on `192.168.88.51:8080`; Redis up

**Payload gaps found (client sends fields the server doesn't store, and vice versa):**
1. Client's `installed-apps/sync` omits `binaryName` / `isBrowser` / `desktopId` / `categories` — server migration-012 columns never populated (`client/Services/LogCollectorService.cs:1714`)
2. Client sends `installedAppId` / `installedPackageId` per app-session, but server `app_sessions` has no such columns (migration 013 needed)
3. Client cgroup fields (`groupedBy` / `cgroupScope` / `contextLabel`) exist on the model but aren't sent; server DTO has no fields
4. Server `app_items` lacks the 10 journey fields + `process_id` the client collects; client mapper doesn't send them either

---

## Part A — Washout PostgreSQL (tracking data only)

1. **Backup** DB first: `pg_dump` → `server/bin/backup/alpha_ai_tracker_<timestamp>.sql` (safety before destructive op)
2. **TRUNCATE** the 12 tracking tables in one transaction:
   - `app_items, app_sessions, browser_contexts, file_explorer_contexts, device_hardware_info, installed_applications, installed_packages, network_info, session_events, shell_commands, urls, url_visits` (with `CASCADE`)
3. **Keep** `users`, `employees`, `departments`, `schema_migrations` untouched
4. **Verify** row counts = 0 and the 5 employees remain

## Part B — Server schema + DTO/model/repo wiring

5. **Migration `013_session_identity.sql`**: add `installed_app_id`, `installed_package_id`, `grouped_by`, `cgroup_scope`, `context_label` to `app_sessions` (+ indexes). No FK constraint to avoid breaking ingestion if a referenced app row was never synced
6. **Migration `014_app_items_journey.sql`**: add `process_id`, `object_type`, `action`, `journey_id`, `sequence`, `previous_path`, `current_path`, `window_id`, `tab_id`, `metadata_json` to `app_items` (+ indexes on journey_id/sequence)
7. **Models** (`server/internal/models/app_session.go`): add new fields to `AppSession` and `AppItem`
8. **DTOs** (`server/internal/dto/new_schema_dto.go`): extend `AppSessionEntry`/`AppSessionResponse` and `AppItemEntry`/`AppItemResponse`
9. **Service** (`server/internal/services/new_schema_service.go`): map new fields in `SyncAppSessions`, `SyncAppItems`, `ListAppSessions`, `ListAppItems`
10. **Repo** (`server/internal/repository/new_schema_repo.go`): extend `BulkInsertAppSessions`, `BulkInsertAppItems` SQL + `ListAppSessions`/`ListAppItems` SELECT/scan
